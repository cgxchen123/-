# 应用效果与证据台账

本文件用于区分“已经证明的工程事实”和“还没有真实证据的应用效果”。

| 指标 | 当前状态 | 写入比赛材料的条件 |
|---|---|---|
| 单元/专项工程测试 | 已有 | 可作为工程实现证据 |
| 真实用户人数 | 待补 | 必须有参与者记录 |
| 普通大模型 vs 芯造天工对照 | 待补 | 统一题目、模型、评分规则 |
| 任务完成时间 | 待补 | 保存原始计时 |
| 关键工程错误数 | 待补 | 先定义错误标准 |
| 人工返工次数 | 待补 | 保存修改前后结果 |
| 真实硬件闭环 | 待补 | 型号、照片/视频、日志和时间 |
| 学校/企业试点 | 未宣称 | 只有正式材料才能填写 |

## 推荐实验

建议做 10–20 名具备嵌入式基础的学生、10–20 个统一任务的对照实验，比较关键工程错误、缺失参数、人工修正次数和任务时间。

这些人数和题量是内部实验建议，不是比赛官方硬性要求。

实验模板：`docs/USER_EVALUATION_TEMPLATE.md`

没有原始记录，就保持“待补”。
