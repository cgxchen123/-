# 芯造天工

> 面向高校嵌入式原型开发的可信 AI 硬件方案生成与风险审查系统

当前稳定版本：**v5.4.0**  
当前赛道：**2026 AIC 第八届全球校园人工智能算法精英大赛｜算法创新赛｜AI+场景创新**

## 项目做什么

芯造天工把自然语言硬件需求转成结构化工程需求，再由 AI 负责意图理解与方案规划，由确定性工程层负责器件、电源、引脚、BOM、证据与风险门禁。

核心原则：

**AI 负责“理解与规划”，确定性工程层负责“验证与放行”。**

证据不足时进入 REVIEW；发现明确工程违规时直接 BLOCKED，避免把生成式模型的不确定性直接当成硬件工程结论。

## 当前能力边界

已经实现：自然语言需求解析、AI Planning-only、器件/电源/引脚/接口约束检查、证据链、Engineering Gate、Fail-Closed、硬件状态模拟/真实串口来源区分、Web 工作台、回归验证。

暂不宣称：全自动 PCB Layout/生产文件、全品类 SPICE、全知识库参数级 Datasheet 自动核验、量产级认证、企业试点收益。

## 开始运行

当前 GitHub 仓库首先承担版本与比赛档案管理；完整可运行源码仍以正式交付包为准，源码迁移状态见 `SOURCE_MIGRATION.md`。

源码完整入库后，再在此处固定唯一的 Windows / macOS / Linux 启动命令，避免 README 与真实目录不一致。

## 历史版本

本仓库不会覆盖历史版本。每次稳定交付都应：

1. 更新 `CHANGELOG.md`
2. 在 `history/` 增加版本条目
3. 保存发布日期、变更点、测试结果和已知边界
4. 对稳定版本建立 Git tag

历史版本索引见 `docs/HISTORY_INDEX.md`。

## 真实性原则

仓库中的测试结果只代表已执行的本地/工程验证，不自动代表真实用户效果。任何用户规模、节省时间、商业收益、企业试点等结论必须有原始证据后再写入项目材料。
